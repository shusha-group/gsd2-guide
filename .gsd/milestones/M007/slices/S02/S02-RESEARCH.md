# S02 Research: Changelog Improvements

**Depth:** Targeted — known tech (Astro/Starlight, marked), moderate integration with existing pipeline.

## Requirements Owned

- **R073** — Changelog summary digest (highlights page with solo-builder-perspective summaries)
- **R074** — Changelog GitHub issue auto-linking (every `#NNN` → clickable link)

## Summary

Two independent deliverables:

1. **Issue auto-linking in ReleaseEntry.astro** — trivial regex on the already-processed `bodyHtml` string. ~958 `#NNN` references across 88 releases become clickable links.
2. **Changelog highlights page** — a new MDX page showing opinionated per-release summaries. Requires either build-time generation or a new pipeline step in `update.mjs`.

## Recommendation

- **Issue linking**: Add a single regex replace to `ReleaseEntry.astro` after the existing command-slug linkification. Pattern: `#(\d+)` not already inside an `<a>` tag → `<a href="https://github.com/gsd-build/gsd-2/issues/$1">#$1</a>`. This is a 5-line change.
- **Highlights page**: Create a new hand-authored MDX page at `src/content/docs/changelog-highlights.mdx` that imports `releases.json` and renders a compact summary view. The summaries should be generated by a new pipeline step in `update.mjs` that writes `content/generated/changelog-highlights.json`. Add sidebar entry above the full Changelog.

## Implementation Landscape

### Issue Auto-Linking (R074)

**File:** `src/components/ReleaseEntry.astro` (lines 68-75 area)

The component already post-processes `bodyHtml` with a regex to linkify `/gsd X` commands. Add a second regex pass immediately after:

```typescript
// Linkify #NNN issue/PR references → GitHub links
// Negative lookbehind for href=" or > to avoid double-linking
bodyHtml = bodyHtml.replace(
  /(?<![\w\/"])#(\d+)\b/g,
  '<a href="https://github.com/gsd-build/gsd-2/issues/$1" target="_blank" rel="noopener noreferrer">#$1</a>'
);
```

**Key constraint:** Must not linkify `#NNN` that's already inside an `<a>` tag or part of a URL. The regex negative lookbehind handles this. GitHub auto-redirects `/issues/NNN` to `/pull/NNN` for PRs, so a single base URL works.

**Count:** ~958 issue references across 88 releases will be linked.

### Changelog Highlights Page (R073)

**Approach:** Two-part delivery:

1. **Pipeline step** in `update.mjs` — after the extract step, generate `content/generated/changelog-highlights.json` by processing `releases.json`. Each release gets a 1-2 sentence solo-builder-perspective summary derived from its `added`/`changed`/`fixed` arrays and `body` text. Use Claude via `claude -p` (same pattern as page regeneration) to generate opinionated summaries, or use a simpler heuristic extraction from the structured fields.

2. **MDX page** at `src/content/docs/changelog-highlights.mdx` — imports the generated JSON and renders a scannable list. Each entry: version, date, 1-2 sentence summary, link to full entry in changelog.

**Existing pipeline structure** (`update.mjs`):
- 10-step pipeline: install → extract → diff → impact → confirm → manage commands → manage prompts → regenerate → build → check-links → stamp
- New step slots naturally after extract (step 2) or after manage prompts (step 7)
- Pattern: each step is a function called sequentially with timing

**Sidebar config** (`astro.config.mjs` line 22): Current entry is `{ label: 'Changelog', link: '/changelog/' }`. Add a "Changelog Highlights" entry above it or restructure into a group.

### releases.json Structure

Each release has: `tag_name`, `name`, `published_at`, `html_url`, `added[]`, `changed[]`, `fixed[]`, `body` (markdown). The structured arrays (`added`, `changed`, `fixed`) are ideal for generating summaries without parsing markdown.

## Natural Seams

1. **Issue auto-linking** — single file change (`ReleaseEntry.astro`), zero dependencies, verifiable immediately with `npm run build`
2. **Highlights generation** — pipeline script work (`update.mjs` + new generator), produces JSON artifact
3. **Highlights page** — MDX page + sidebar config, depends on generated JSON existing

Task 1 is fully independent. Tasks 2-3 are sequential.

## Risks

- **Regex edge cases**: `#NNN` inside code blocks, headings with `#`, or markdown headers. The marked output converts markdown to HTML first, so `#` headers become `<h1>` etc. Code blocks become `<code>`. The regex should avoid matching inside tag attributes. The negative lookbehind `(?<![\w\/"])` handles most cases.
- **Highlights generation quality**: If using Claude for summaries, it's a slow pipeline step (~5min for 88 releases). Consider generating once and caching, only regenerating for new releases. Alternatively, use a heuristic: concatenate the first item from each of `added`, `changed`, `fixed` arrays.
- **Astro regex support**: Astro components run in Node, so lookbehinds are supported (Node 16+).
