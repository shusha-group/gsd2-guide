# M007: Guide Consolidation & Usability

**Gathered:** 2026-04-02
**Status:** Ready for planning

## Project Description

The GSD 2 Guide is a community documentation site built with Astro Starlight, hosted on GitHub Pages. It provides narrative-first documentation for solo builders using GSD 2. This milestone consolidates the guide with official GSD 2 docs, adds missing usability features, and improves the changelog experience — reducing friction for solo builders who currently need to jump between two documentation sources.

## Why This Milestone

Users bounce between the guide and the official GSD 2 README/docs. The changelog has 88 releases of detail but no summary layer. 875 issue references are unlinked. New users face 50+ commands with no quick-start path. Nobody helps a potential user decide whether GSD suits their project.

## User-Visible Outcome

### When this milestone is complete, the user can:

- Scan a changelog highlights page to understand what changed in any release, in under 60 seconds
- Click any `#NNN` issue reference in the changelog to go directly to the GitHub issue
- Find the 10-15 most-used commands on a single curated quick-reference page
- Assess whether GSD is right for their project in 30 seconds via a decision guide
- Learn how to write effective requirements from concrete bad-vs-good examples
- See approximate dollar costs for typical milestones at different scales
- Stay within the guide for 90% of their solo-builder workflow without visiting the official docs

### Entry point / environment

- Entry point: Browser, GitHub Pages URL
- Environment: Static site, no server dependencies
- Live dependencies involved: GitHub API (for releases.json extraction during build), Claude API (for pipeline-generated content during `npm run update`)

## Completion Class

- Contract complete means: all pages build, all internal links resolve, all new content exists with correct structure
- Integration complete means: changelog highlights are generated by the update pipeline; issue links render correctly from releases.json
- Operational complete means: `npm run update` produces correct changelog highlights for new releases; `npm run build` passes; `npm run check-links` passes

## Final Integrated Acceptance

To call this milestone complete, we must prove:

- A new user can navigate from the landing page → "Is GSD right for me?" → Quick Reference → their first command, without leaving the guide
- The changelog highlights page renders with summaries for recent releases, and clicking "Full changelog" shows the existing detail view
- Every `#NNN` reference in the rendered changelog is a clickable link to `https://github.com/gsd-build/gsd-2/issues/NNN`
- Cross-referenced content (auto mode, .gsd/ structure, verification ladder, v1→v2) exists in the guide in narrative form
- No existing URLs are broken

## Risks and Unknowns

- Changelog summary generation quality — AI-generated summaries must be opinionated and useful, not generic
- Pipeline integration for highlights — adding a new generation step to `npm run update` without breaking existing flow
- Navigation restructure URL stability — moving pages or changing sidebar groups must not break existing links

## Scope

### In Scope

- Changelog summary digest page with pipeline generation
- Render-time GitHub issue link auto-linking in ReleaseEntry.astro
- Curated quick reference page (10-15 commands)
- Cross-referenced content consolidation (7 content areas from official docs)
- "Is GSD right for me?" decision guide
- "Writing a good brief" guide
- Concrete cost examples with dollar ranges
- Sidebar/navigation restructure

### Out of Scope / Non-Goals

- Rewriting existing Solo Guide sections 1-8
- Duplicating full official configuration reference
- Video or interactive tutorial content
- Hosting/deployment changes

## Technical Constraints

- Astro Starlight MDX/MD with frontmatter
- Australian English throughout
- All hand-authored pages go directly in `src/content/docs/` (not managed by prebuild pipeline)
- Changelog data comes from `content/generated/releases.json` — source of truth is the official GSD 2 CHANGELOG.md
- GitHub issue links target `https://github.com/gsd-build/gsd-2/issues/` or `https://github.com/gsd-build/gsd-2/pull/`
- No existing URLs may break

## Integration Points

- `npm run update` pipeline — changelog highlights generation must integrate as a new step
- `ReleaseEntry.astro` — issue link transform must be added to the `marked` post-processing
- Sidebar config in `astro.config.mjs` — navigation restructure
- `npm run check-links` — must pass after all changes
