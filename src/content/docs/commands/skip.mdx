## What It Does

`/gsd skip` registers a work unit in `.gsd/completed-units.json` so that auto-mode treats it as already done and never dispatches it. No agent runs, no artifacts are written — the unit is simply blacklisted from the dispatch loop for the current milestone.

The primary use case is course correction mid-auto. When a task or slice is no longer relevant — because the plan changed, a dependency was removed, or the work was done out-of-band — skip prevents auto-mode from wasting tokens re-running it. It is not destructive: plan files, roadmap checkboxes, and slice documents are left untouched.

Skip is scoped to the current milestone. When auto-mode completes the milestone and transitions to the next one, it archives `completed-units.json` (renaming it to `completed-units-<MID>.json`) and resets the list to empty. Skipped units from the previous milestone do not carry forward.

## Usage

```
/gsd skip <unit>
```

The argument accepts several forms, from most explicit to most convenient:

```
/gsd skip execute-task/M001/S01/T03    Full unit key (most explicit)
/gsd skip M001/S01/T03                 Milestone path — expands to execute-task/M001/S01/T03
/gsd skip T03                          Task shorthand — expands using active milestone + slice
/gsd skip S02                          Slice shorthand — expands to plan-slice/{mid}/S02
```

Running the command without an argument shows usage:

```
/gsd skip
→ Usage: /gsd skip <unit-id>  (e.g., /gsd skip execute-task/M001/S01/T03 or /gsd skip T03)
```

### Key Format

Unit keys stored in `completed-units.json` follow the pattern `<unitType>/<unitId>`:

| Unit type | Key example | When to use |
|-----------|-------------|-------------|
| `execute-task` | `execute-task/M001/S01/T03` | Skip a specific task in a slice |
| `plan-slice` | `plan-slice/M001/S02` | Skip planning for an entire slice |
| `research-milestone` | `research-milestone/M001` | Skip milestone research phase |
| `complete-slice` | `complete-slice/M001/S01` | Skip slice summarization |
| `complete-milestone` | `complete-milestone/M001` | Skip milestone completion unit |

### Shorthand Expansion

When the argument does not include a recognized unit type prefix (`execute-task`, `plan-`, `research-`, `complete-`), GSD expands it automatically:

- **`T##` pattern** — Derives the active milestone and slice from the current project state, then expands to `execute-task/{mid}/{sid}/{T##}`. Requires an active milestone and slice to be set.
- **`S##` pattern** — Derives the active milestone and expands to `plan-slice/{mid}/{S##}`.
- **Path with slashes but no prefix** — Prepends `execute-task/`. This handles inputs like `M001/S01/T03`.

### Idempotency

If the resolved key is already present in `completed-units.json`, GSD reports `Already skipped: <key>` and exits without modifying the file. Running `/gsd skip T03` twice is safe.

### Milestone Transition

When auto-mode advances to a new milestone, it archives the current `completed-units.json` as `completed-units-<MID>.json` and resets the file to an empty array. Skipped units from the previous milestone do not block units in the next one.

### Worktree Isolation

When auto-mode runs in worktree-isolated mode, `completed-units.json` is synced from the project root into the active worktree at the start of each milestone. Skips written via `/gsd skip` in the main terminal are propagated to the running worktree agent.

### Doctor Integration

[`/gsd doctor`](../doctor/) checks `completed-units.json` for orphaned keys — entries that reference units whose expected artifacts are missing from disk. These can appear if artifacts were deleted after a unit completed normally. Doctor flags them as warnings and can remove them with `--fix`, allowing auto-mode to re-dispatch those units.

## What Files It Touches

### Creates

| File | Purpose |
|------|---------|
| `.gsd/completed-units.json` | Created with the new key if it does not already exist |
| `.gsd/` | Created if it does not exist |

### Reads

| File | Purpose |
|------|---------|
| `.gsd/completed-units.json` | Read to check for duplicate entries before appending |

### Writes

| File | Purpose |
|------|---------|
| `.gsd/completed-units.json` | New key appended to the JSON array |

## Examples

Skip a specific task using shorthand (active milestone M001, active slice S01):

```
> /gsd skip T03

● Skipped: execute-task/M001/S01/T03. Will not be dispatched in auto-mode.
```

Skip using a full milestone path:

```
> /gsd skip M002/S03/T01

● Skipped: execute-task/M002/S03/T01. Will not be dispatched in auto-mode.
```

Skip an entire slice's planning unit:

```
> /gsd skip plan-slice/M001/S04

● Skipped: plan-slice/M001/S04. Will not be dispatched in auto-mode.
```

Attempting to skip an already-skipped unit:

```
> /gsd skip T03

● Already skipped: execute-task/M001/S01/T03
```

The resulting `completed-units.json` after skipping two tasks:

```json
["execute-task/M001/S01/T03", "execute-task/M001/S02/T01"]
```
